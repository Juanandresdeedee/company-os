# Change

`change/` contains strategic projects that transform the business toward the goal. Each project should connect to today's diagnosis, the thesis, and a target operating change.

## What belongs here

- strategic transformation projects
- outcome definitions
- owners, start dates, end dates, risks, and success metrics
- target operating change
- project reflections and learnings that should be harvested into run processes, playbooks, or skills

## What does not belong here

- recurring processes
- ordinary task tracking
- code implementation
- generated drafts
- raw research material

## Recommended files

- `projects.md`
- `lessons/`

## Project standard

Each project should answer:

- Which current problem does this address?
- Which thesis does it support?
- What measurable outcome proves success?
- Who owns it?
- What are the start and end dates?
- What contributors and resources are needed?
- What milestones show progress?
- What risks need mitigation?
- What run process will absorb the change after completion?

## Prompts for operators

- What must change for the strategy to become true?
- What projects create new capability rather than just activity?
- What will be different in the operating system when this project ends?
