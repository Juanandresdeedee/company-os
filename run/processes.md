## Process definition

Use this structure for each process.

### Process name

Name the process in plain language.

### Purpose

Explain why this process exists.

Link it to `strategy/thesis.md` and, where useful, `strategy/today.md`.

### Owner

Name the person or function that owns the process.

The owner is accountable for keeping the process useful and reviewed.

### Cadence

State when the process runs.

For example:

- weekly
- monthly
- quarterly
- yearly
- triggered by a specific event

### Inputs

List what the process needs before it starts.

Include source systems and required context.

### Activities

List the work the process includes.

Keep this to repeatable actions, not one-time tasks.

### Metrics

Define 3 metric types.

| Metric type | question | metric | source |
| --- | --- | --- | --- |
| Activity | What will we do? |  |  |
| Quality | How will we know we do it right? |  |  |
| Outcome | What outcome should this create? |  |  |

### Decisions

List the decisions this process should produce.

### Outputs

List the durable outputs, systems updated, or decisions recorded.

### Failure signals

List what shows the process is not working.

### Review

State when the process should be reviewed, changed or removed.

## Prompts

- Which recurring processes keep the company in rhythm?
- Which process should be added, removed, or improved?
- Which metrics belong inside each process?
